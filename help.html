What the Words Mean

Seven words do most of the work in this program, and they are worth getting straight before anything else.

SOURCE - where or who the item came from. A donor, a purchase, a find.

LOCATION - where it physically is now. Storage Room 1/Shelf 4/Folder 5, Cemeteries/Hill Top, Streets/Maple St. A location can be as deep as you like; each part after a slash is a folder inside the one before it.

CATEGORY - what the item is, for finding it by subject: Vehicle, Photo, Children, Military/War/WWII, Minerals/Quartz. You make these up to suit the collection, and an item can carry up to sixteen of them. Past that the program says so and takes no more.

TITLE - a short description, which serves as the item's caption and as the name it is filed under in every folder it appears in. Two items may have the same title.

DESCRIPTION - the story: what the item is, what it is made of, how big it is, what condition it is in. There is no length limit worth worrying about.

PROVENANCE - the record of ownership and history, used as a guide to authenticity. Not required, and the part nobody can reconstruct later.

ITEM - one entry in the collection: a file, a record of the fields above, and a thumbnail, kept together.

Three more that describe the program rather than the item.

THE THREE LISTS - Source, Location and Categories, down the left of the screen. They are folders holding the items, and clicking through them is how you walk the collection.

THE ID - a short code on each item, worked out from the file attached to it. It is not a number handed out in turn. There is a section on it below, because two useful things follow from it.

RESULTS - the folder a search puts its findings in, and what the reports are built from.

Installing It, and Registering

The program runs on Windows, on a Mac and on Linux. It will work on a modest machine, and a bigger collection asks for more disk rather than more computer. A screen of 1920 by 1080 is a comfortable size to work at; on a 4K screen set the Screen choice in Adjust Screen Settings to 4K so the type and the lists come up at a sensible size.

Installing. Run the setup file and take the offered answers. It puts the program in place and leaves your collections alone - they are kept apart from the program, in your own user folder, which is what makes the next part safe.

Updating. Run a newer setup file over the top of the old one, the same way. The collections, the settings and the list of people are untouched, because none of them live in the program's own folder.

Registering. Until a copy is registered it works as a trial and stops at a hundred items. The code you were sent by email goes in from the Reports and More menu, at the item that reads Register Digital Filer until a copy has been registered and Create New Collection afterwards. Paste the code in, and the program restarts to take it up.

If the code names a collection you already have, it opens that one and applies the registration to it rather than starting an empty collection beside it.

More Than One Collection

One copy of the program can hold several collections, each entirely separate: its own items, its own folders, its own title in the window. A historical society and a personal collection of minerals can sit side by side without ever mixing.

Which one you are in is shown in the title bar across the top, and the drop-down above the Source list is how you change it. Picking another collection loads it: the lists are read again and the screen clears, which on a large collection takes a moment and says so.

To make a new one, use the registration item on the Reports and More menu, described just above. Each collection comes from its own code.

To get rid of one, take its items out first - make a full backup of it, then use Delete Items Contained In A Backup File on that backup, which empties it while leaving you the backup to change your mind with. Then run Rebuild Archive. Finding nothing left, it asks whether the collection should go, and if you say yes it is taken off the list. The folder itself stays on disk untouched, so nothing is lost in the moment of saying yes.

Adding an Item, Start to Finish

Five things are needed before an item can be saved: a source, a location, at least one category, a title and a description. The Save button stays greyed out until all five are there, so a Save you cannot press means one of them is missing.

  1. Press Add. The screen clears and goes into Edit Mode, ready for something new.
  2. Press Attach Picture Or Other File and choose the photograph, document, sound or video. It is copied into the archive and the file you picked is left where it was. Attaching nothing is allowed, and the program then makes a file out of what you typed instead, but an item with a picture is worth far more to whoever opens it later.
  3. Press SOURCE and click, in the list on the left, who the item came from. If the name is not there, add it on the Add Source tab at the bottom left. If nobody knows, DONOR UNKNOWN is a real answer and the item still saves.
  4. Press LOCATION and click where the item physically is. NOT PLACED counts here in the same way.
  5. Press CATEGORIES and click one, or several. Clicking a category you have already chosen removes it again.
  6. Type the title in the box at the top. It is the name the item is filed under in every folder it appears in, so write it the way you would want to find it.
  7. Fill in the description: what the item is, with any distinguishing details, materials, dimensions and condition. Provenance, underneath, is for previous owners, dates and history. It is not required, and it is the part nobody can reconstruct later.
  8. Press Save.

Nothing at all is written until Save is pressed, and Cancel Changes leaves the item exactly as it was.

Entering a run of similar items is quicker than this list makes it look. The SOURCE button pressed three times fills in the last item's source, a fourth press adds the location, and a fifth the categories, so the second item of a box usually needs only a title, a description and the file.

Why an Item Has an ID, and the One Rule

Every item carries an ID, shown on the item screen as something like A1B-2C3. It is not a number handed out in order. It is worked out from the file itself, from the picture or document attached to the item, so the file and the ID are one fact written two ways. Two things follow, and both turn up in ordinary use.

The same file cannot be added twice. Attach a file that is already in the collection and the program says so and stops, because that file is what tells one item from another. It offers the two honest ways out: attach it to this item as a display picture, or change the file itself - a single different pixel is enough - so that it genuinely is a different file. This is deliberate. Two items that are the same file are not two items.

One copy of your file is filed in several places at once. An item filed under a source, a location and three categories shows up in five folders, and it is the same single file each time rather than five copies of it. A collection does not swell because its items are well filed.

And the rule that protects both: do your renaming, moving and deleting inside the program, not in Explorer or Finder. A file altered out there no longer matches its ID, and the program can no longer tell that the item is itself - which is how the same thing can end up in the collection twice. The folders you browse are also built fresh each time Rebuild Archive runs, so anything put into them by hand is gone at the next rebuild. The items are what those folders are built from, and they are the thing to look after.

Changing an Item That Is Already In

Find the item first. Click through the Source, Location or Categories lists to the folder it is in, and if the folder holds several items the navigation bar and the two arrows step through them. A search is the other way in, and what it finds lands in the RESULTS folder.

With the item on screen press Edit. Every box can be changed. Source and Location are picked the same way as when the item was entered. Categories toggle: click one to add it, click it again to take it off. The file itself is changed with Attach Picture Or Other File, and because the file is what gives the item its ID, replacing it gives the item a new one - which is the one case where that happens.

Nothing is written until Save, and Cancel Changes puts every box back to what it was.

Moving Something to Another Place

A location is a path, and the slashes in it are real containers inside one another. CORNER CABINET\BOX 1 means box 1, which is in the corner cabinet; CORNER CABINET\BOX 1\TRAY 2 is a tray inside that box. The lists down the left draw it as folders inside folders because that is what it is.

So when the box itself is moved - out of the corner cabinet and onto shelf 7, say - what you want is for every item in it, and everything nested inside it, to come along. That is one job in this program, not one job per item.

Moving One Item

Press Edit, press LOCATION, and click the new place in the list. If the place does not exist yet, add it with Add or Edit Location first. Press Save. That item is now filed there and nothing else has changed.

Moving a Whole Box, with Everything In It

This is the one for a real move: the box has gone somewhere else, and its contents went with it.

  1. Press Browse and walk to the box: open (LOCATION), then CORNER CABINET, then BOX 1. You are now standing in the folder that is going to move.
  2. Press Move Directory at the bottom. A screen opens titled Move This Folder - choose destination.
  3. Click where it is going - BOX COLLECTION - and press Move Here. The box keeps its own name and becomes part of what you clicked, so CORNER CABINET\BOX 1 becomes BOX COLLECTION\BOX 1, the same as dragging one folder onto another.
  4. You are told how many items are about to be moved and asked to say yes. Read the number: it should be the number of things in that box. Then it works through them, counting as it goes, and says MOVE COMPLETE with the old and new addresses.

Typing a destination instead. The same screen has a box to type in, and what you type is the whole new address rather than a parent to sit under: type BOX COLLECTION\BOX 1 and that is exactly where it lands. Typing is also the way to move something into a place that does not exist yet - STORAGE ROOM 2\SHELF 4 is made on the way - and (TOP LEVEL) at the head of the list means no parent at all, a place of its own.

What actually happens. Every item whose location starts with the old path has that part of it rewritten, so the box, the trays inside it and every item in any of them all travel together and keep their arrangement. The folders you browse are relinked to match, and folders left empty by the move are cleared away.

The items themselves are not touched. The files stay exactly where they are in the archive, the IDs do not change, and nothing is copied - only the address written on each record, and the folders built from it.

There is no undo button for this. There is no need for one either: moving it back is the same job in the other direction, and the program tells you the count before it starts, which is the moment to notice if you are standing in the wrong folder.

The Other Way In

From an item rather than from the browser: press Edit on any item in that box and press Add or Edit Location. The box's own address is already filled in beside Rename From - it is the address the item you are on carries, which is why you open this from an item in the box you mean to move. Type the new address beside Rename To and press Rename / Move Location. It is the same move, with the same confirmation and the same count - it simply starts from an item you have in front of you instead of from the folder.

This is also how a place gets a better name. The old address and the new one are both just text; renaming BOX 1 to MAPS AND PLANS and moving BOX 1 under BOX COLLECTION are the same operation, which is why one button does both.

Categories Move the Same Way

Everything above works on a category as well. Browse into the category and press Move Directory, or use Add or Edit Categories and its rename button. A category that has a display sheet keeps it, and sub-categories travel with their parent exactly as trays travel with their box.

Sources are different: an item's source is where it came from, which does not change because the thing was put somewhere else. There is no move for a source folder, and there should not be.

Deleting: One Item, or Several

Delete removes the item you are looking at, entirely, and one is all it removes. It asks first, and once you have said yes that item is out of the collection: out of every folder it was filed in, out of the lists, out of the reports. There is no undo. Treat it as gone, because it is.

It is not the preferred way to delete. It is there for the single obvious mistake - the duplicate, the picture of the inside of a lens cap - where there is nothing to think about. For anything else, use the way described below, which asks you to make a backup file first and so hands you the means of changing your mind.

Deleting Several, and Keeping a Way Back

Clearing out a group of items is done through Backing Up and Restoring, on the Reports and More menu, in two steps: make a backup of the items that are going, then delete them using that backup file.

  1. Search for what is to go, so that those items are the ones in the (RESULTS) folder. Run several searches if it takes several - results add up rather than replacing each other - and look through RESULTS until it holds exactly what you mean to remove.
  2. Open Backing Up and Restoring, choose Backup (Export) Result Folder and press Accept. You are asked where to put the file; it is given a name ending .VAB, and it holds those items whole.
  3. In the same screen, choose Delete Items Contained In A Backup File, press Accept, and pick the file you have just made. Exactly the items in that file are removed from the collection, and nothing else is touched.
  4. Run Rebuild Archive afterwards so the folders you browse match what is left.

The same file brings them back. Deleting with it does not consume it or change it - it is a file of its own, outside the collection - so changing your mind needs nothing clever: open Backing Up and Restoring again, choose Restore (Import) Backup File, and pick that same file. It is the ordinary restore, doing the ordinary thing, and the items return with their sources, locations, categories, titles, descriptions and pictures exactly as they were.

That is the whole reason this is the preferred way round. The file you had to make in order to delete is the same file that undoes it, so the undo exists before the deletion does. Nothing has to be remembered, and nothing has to be dug out of anywhere.

So the order of work is: gather, back up, delete. Keep that .VAB somewhere sensible for as long as there is any chance of wanting those items again - a year, say, or for ever if the disk can spare it. It is the only way back, and it costs nothing to keep.

This is also how part of a collection is handed to somebody else, or split into a collection of its own: the same backup file that lets you undo the deletion is the file they restore at their end. There is a section on backing up below that goes through all of it.

Importing a Whole Folder

A folder of scans or photographs can come in all at once instead of one item at a time. It is on the Reports and More menu as Import a Folder..., and the screen says what it is about to do before it does it.

  1. Tick what to bring in: Pictures, Music, Video, Documents, or Everything in the folder, whatever it is. If what you want is not one of those, type the file types in the box instead, like tif, cr2, wav.
  2. Press Choose Folder... and pick the folder. Everything in it, and in every folder inside it, is considered.
  3. Fill in the Source and Location that will go on the whole batch, and press OK.

"Everything in the folder, whatever it is" brings in literally everything under the folder you choose, without asking file by file - which is the point of it, and exactly why it is worth a moment's thought before pointing it at a folder you have not looked through yourself. An old folder can hold more than you remember: thumbnails and cache files a camera or a phone left behind, a stray download, half a dozen near-duplicates of the same shot. None of that is sorted out on the way in - it all becomes items - and taking it back out afterwards means finding and deleting each one by hand rather than one folder you could have left out to begin with. Know roughly what is in a folder before choosing Everything on it; where you do not, tick just the kinds you actually want and the rest is left alone.

Both of those boxes can be left empty, and what happens then is useful rather than a fallback. An empty Source files the batch under the date and time the import was run, which is how you find that one batch again afterwards. An empty Location groups the items by what they are - PICTURES, MUSIC, VIDEO or FILES - with one exception: an .MP3 that carries its own artist and album tag is filed by them instead, as MUSIC\ARTIST\ALBUM, stopping at the album so that every song on it still shares one folder to browse rather than each sitting alone in one of its own. A track number in the tag goes onto the front of the title, not into the location.

Each file becomes an item, and it is the item's category - not its location - that keeps the folder structure you already had: filed under IMPORT, by the same file-type grouping as above, and then by the one folder immediately holding the file, rather than the whole chain of folders above it. The filename becomes the title, and a song uses the title in its own tag if it has one. Whatever a file knows about itself is kept: the camera and the date from a photograph, the artist and album from a song, the author and title from a document.

Nothing in the folder you point at is moved, renamed or altered - the files stay exactly where they are and the collection gets its own copy. A file that is already in the collection is recognised and skipped, so running the same import twice does not bring anything in twice.

What the import cannot do is write your descriptions. The items arrive with a title, a source, a location and their categories, and the description box is empty and waiting. That is the work; the import is only the carrying.

What Rebuild Archive Does, and When to Run It

Rebuild Archive is on the Reports and More menu. It throws away the folders you browse - the source folders, the location folders, the categories, the albums - and builds every one of them again from your items.

That sounds alarming and is not, because those folders were never where anything was kept. They are a way of looking at the items, built out of what each item's record says, and they can be made again at any time. Your items are not rebuilt. They are what the rebuild is built from.

Run it when the folders and the items have got out of step:

  • after restoring a backup - though the program runs it for you then;
  • when a folder looks wrong, or empty, or an item is not where it should be;
  • after anything has been moved about underneath the program.

It shows a bar and a percentage while it works, and a collection of several thousand items takes minutes rather than seconds. Closing the window stops it: it tells you how many items it managed and asks you to run it again to finish, and because it starts over from the items each time, stopping costs nothing but the time already spent.

Backing Up, and Putting a Collection on Another Computer

Backing Up and Restoring on the Reports and More menu does both jobs, and the screen is in three parts: make a backup, delete items using a backup, and restore from a backup.

To make one, choose Full Backup and press Accept. You are asked where to put it, and the box opens in your home folder rather than in the collection, because the one place a backup must never go is inside the thing it is backing up. Put it on another drive - the drives you can reach are listed down the side of that box. The file is given a name ending in .VAB and it holds the whole collection: every item, every record, the thumbnails, the categories, the album order and the accession records.

It is written under a temporary name and only given its real one once it is finished and has been checked. A backup that was interrupted is therefore never left sitting there under the name of a good one, which is the worst way for a backup to fail.

To send somebody part of a collection rather than all of it, search for what they should have so that it lands in the RESULTS folder, then choose Backup (Export) Result Folder. That makes a .VAB of only those items.

To put a collection on another computer:

  1. Install the program there and open it.
  2. Make the collection: Create New Collection on the Reports and More menu, and give it a name. On a copy that has not been registered yet, that same menu item reads Register Digital Filer and asks for the code you were sent instead.
  3. With that collection open, go to Backing Up and Restoring, choose Restore (Import) Backup File, press Accept, and pick the .VAB file.
  4. Let it finish. It says REBUILD ARCHIVE next and then does it for you.

Restoring adds what is in the backup to the collection that is open. It does not replace it and it does not empty it first, which is what makes it useful for joining two bodies of material as well as for moving one. The same choice can change what the items say as they come in: fill in Change Source, Change Location or Add Category before pressing Accept, and every item in the backup arrives with that instead. Leave those boxes empty and the items come in exactly as they were.

A Routine Worth Keeping

Knowing how to make a backup is not the same as having one. What works, from societies that have been doing this for years: a full backup onto two drives once a year, one kept where the collection is and one kept somewhere else entirely - a board member's house, another building - so that one fire or one theft cannot take both. Make another whenever you have just done a season's worth of entering, while it is fresh enough to be worth protecting.

Write the date on the drive, keep the last one rather than writing over it, and eject the drive before pulling it out - on Windows through the arrow at the bottom right of the screen, on a Mac by dragging it to the wastebasket, on Linux with the eject symbol beside its name. The file is large and the last of it may still be being written when the copying looks finished.

And test one. Restoring a backup into a spare collection, once, tells you the drive is readable and the file is whole - which is a thing worth knowing before the day you need it.

Delete Items Contained In A Backup File is the other direction: it removes from this collection exactly the items that are in the backup file you choose. This is the preferred way to delete anything more than a single obvious mistake, because the file itself is untouched - restoring that same file afterwards puts every one of those items back.

Searching: What Is Looked At, and How

Type into the search box on the Search tab and press Search, or just press Enter. Capital letters make no difference.

What is searched is the whole of an item's record, not only its description: the title, the description, the provenance, the source, the location, every category, the dates, the file type, and anything a photograph or a song brought in with it. That is why an item can come back for a reason that is not visible in its description, and why the match is marked in SOURCE, LOCATION and CATEGORIES as well as in the words.

What you type is looked for as one piece of text. There is no wildcard, and there is no way to ask for two words in different places: BRAGG FARM finds records where that runs together as written, not records that happen to hold both words apart. Shorter is therefore usually better - BRAGG finds everything BRAGG FARM would have, and more.

Searching for a single full stop . returns every item in the collection. Every record stores the file's extension with its dot, so a full stop is in all of them.

The tick box Search "Entered by" field changes what is looked at rather than adding to it: with it ticked, the search looks only at who entered the item, which is how you find a volunteer's work for the afternoon. Untick it to go back to searching everything.

A search of two letters or fewer finds items but marks nothing, which stops a short word painting the whole screen yellow.

A search of a large collection is not instant - several thousand items take a little while, and the bar across the top is there to say that something is happening rather than nothing. When more than one item is found, the navigation bar shows which of how many you are looking at, and the arrows move through them.

The RESULTS Folder, and Sharing Part of a Collection

Everything a search finds is put into a folder called (RESULTS), and that folder is what the rest of the program works from when it is asked to produce something.

A search adds to it and never empties it. Search for one family, then another place, then a year, and all three sets are gathered together - and an item already there is not put in twice. The only thing that empties it is the Clear Results Folder button.

Clearing it deletes nothing. What sits in that folder is the same single file the item already is, shown there as well; removing it removes the showing, not the item. The same is true of the folders you browse.

Two more buttons sit beside it. Add Selected Directory to Results puts everything in the folder you are looking at into RESULTS, which is how to gather a whole category without searching for it. View Result Folder shows you what you have collected so far.

Once it holds what it should, there are three things to do with it:

  • Spreadsheet of (RESULTS) directory on the Reports and More menu writes a spreadsheet of them;
  • Backup (Export) Result Folder on the Backing Up and Restoring screen makes a .VAB of just those items, which is how you send somebody part of a collection;
  • and anything you then do to the items themselves is ordinary work - RESULTS is a way of holding a set, not a copy of it.

A Spreadsheet of the Whole Collection

The 'Spreadsheet of (RESULTS) directory' option builds its report from whatever is in the RESULTS folder, so to get a report covering everything, first put everything into RESULTS: search for a single full stop . and every item in the collection is returned.

This is complete, not an approximation. The search reads the whole of an item's record, not just its description, and every record stores the file's extension with its dot - .JPG, .MP3 - so a full stop is always present, whatever the item is called and whatever was typed about it.

The FILE column, the fifth one, is a link rather than just a name: click it in the spreadsheet and the item's own file opens, so a line you are reading about can be looked at without coming back to the program. The LOCAL FILE LOCATION column near the end links the same way to where the item is filed under its source.

The spreadsheet is written as Full_Report.xlsx in the collection's data folder, and opens in whatever application handles spreadsheets on this computer. If nothing does, the file is still created and a window opens showing you where it is. Close the report before creating a new one - the file is overwritten in place, and a spreadsheet program holding the old copy open will go on showing the old figures.

Albums, the Order They Are In, and a Book

An album is a category like any other. Put the items into it the way you file anything else, and what makes it an album is that you can decide the order they are in instead of leaving them in the order they were entered.

Open the category, press Edit, and the Album Order button appears. It opens a screen of small pictures, numbered in their current order.

  1. Click the picture you want to move. It turns green.
  2. Click the picture you want it to sit at. The first one moves there and everything else shuffles along.
  3. Click a green picture again to change your mind instead of moving it.
  4. Press Save Changes when the order is right, or Quit Without Saving to leave it as it was.

Slides Across sets how many pictures are shown on a row, which is for your eyes while you work and has nothing to do with the order itself.

The order is kept with the category and is what you see from then on, in the folder and in a slideshow.

A slideshow. The Hide Tree button puts the picture up on the whole window with the lists out of the way, and steps through the items in the folder you are in. How long each one stays up is the slider beside it, and at nought it simply stays on the picture you are looking at, which is the way to show one item across a room. The slider is only there when Slideshow Timer is ticked in Program Settings. Press the same button, now reading Show Tree, to come back.

A book. With Create Book From Album ticked in Program Settings, the Album Order screen also offers Create Book. It makes a document of the album in the order you have just set: each picture at the size and position the card format gives it, with the title, the description and the provenance under it. It is written into a folder called Virtual Archive Output in your home folder, with the date and time in its name so a new one never writes over the last, and it opens in whatever handles documents on this computer.

The Create Screen: a Display Sheet for an Item or a Category

Highlight the item, or the category in the CATEGORIES list, then open the Reports and More menu and choose Create Display Sheet. The screen that opens has its controls at the top and the page itself underneath them: everything you change is redrawn there as you change it, so nothing has to be guessed at or produced to be looked at.

What Would You Like to Create?

Two choices at the top, and they decide which set of controls is on screen.

This Item is chosen when the screen opens. It makes a card for the one item you had highlighted.

This Category makes a page of a whole category: a heading, your own words, and every item in it. It is greyed out, with no category selected beside it, if you did not come in from a category - the reason is put next to the control rather than left for you to work out.

For One Item

Pick Template - the list of card layouts. Left on its first entry, the card is the program's own. Choose one of yours and it asks Build the page with this layout? with Run and Cancel, so a layout picked by accident costs nothing. The list then returns to its first entry, which is deliberate: it means choosing the same layout again still does something.

LEFT, CENTER, RIGHT and NONE - where the picture sits on the card. NONE leaves the picture off and gives the whole card to the words. These apply to the program's own card; a layout of your own puts things where its own design says.

Picture Size - how wide the picture is drawn, from about an inch to eight. A printed page takes at most six and a half inches of it, so a picture cannot run off the paper however far the slider goes.

orientation - the small grey word over at the right, for a picture that is on its side. It is quiet on purpose: it is rarely wanted and it changes the item rather than the page. Press it and it asks first; say yes and turn left and turn right appear, a quarter turn each. The word itself becomes Press When Done, and pressing it puts the arrows away. It is offered for one item only - a category has no single picture a turn could mean.

View In Browser - builds the card and opens it in whatever shows web pages on this computer, ready to print.

For a Category

Category - which category the page is for, named here so you can see at a glance that it is the one you meant.

Heading - the title that goes across the top of the page.

Words - what goes under the heading: a paragraph about the collection, the gift, the exhibition, whatever the page is for.

Both of those are kept with the category. Come back to it next month and they are still in the boxes. Clear them both and the page is removed.

Layout - how the page is laid out. The first entry is the program's own STANDARD PAGE; under it are your own layouts; and EDIT OR CREATE A NEW TEMPLATE opens the layouts screen described below. Choosing one of your page layouts asks Run or Cancel first, the same as the card list does.

A Word layout - a book template, ending .docx - behaves differently and says so: the button at the bottom changes to View File. Nothing is built when you pick it. Pressing the button then starts a fresh copy of that template, fills it from the category's own folder and opens it, so a book is never built on top of the last one.

View In Browser - builds the page and opens it. The preview on screen shows the first twelve items, which is enough to see what the page will look like; the page it makes holds up to four hundred.

Layouts of Your Own

EDIT OR CREATE A NEW TEMPLATE, on either list, opens a screen of the layouts you have and the ones the program came with. Edit It opens one of yours to change, in whatever handles that kind of file. What a Layout Can Ask For

Open Sample of all fields, the layout the program comes with, in a text editor, and short words in capitals between hash signs stand out everywhere: #HEADING#, #TITLE#, and so on. Each one is a marker. Wherever it sits in your file, the finished page has something real put there instead - the category's own heading, one item's own title - and everything else, every tag, every colour, every word you typed yourself, is left exactly as you wrote it.

Some markers are filled once, from the category itself, however many times they appear on the page:

#HEADING# - the title typed into the Heading box.

#CATEGORYTEXT# - the paragraph typed into the Words box.

#CATEGORY# - the category's own name, exactly as it is filed.

#ORGANIZATION# - your collection's name.

#COUNT# - how many items are on the page.

#ACCESSIONNUM# - a fresh accession number for the batch, worked out new each time, the same kind a single card gets.

#LOGO# - your report logo, already a complete picture rather than a filename. Put the marker itself where the picture should sit; there is nothing to put it inside.

The rest are filled once for every item, and only work between a pair of #EACH# and #END# markers. Put those two around whatever should repeat - one cell of a table, say - and the program copies that piece once for every item in the category, filling it fresh each time:

#TITLE# - the item's name.

#THUMB# - the item's own picture, already complete; #FILENAME# is the same marker, under the name a card layout knows it by.

#DESCRIPTION#, #PROVENANCE# and #METADATA# - the item's own description, provenance and metadata.

#ID# and #SOURCE# - the item's short identifier, and who it came from.

#NUMBER# - which one this is on the page: 1, 2, 3 and on.

#NEWROW# - put at the very front of the repeated piece, it becomes a new table row every three items, and nothing at all on the first.

A category page is not the donor's own business card, so #DONOR#, #ADDRESS#, #CITY#, #STATE#, #ZIP#, #PHONE# and #EMAIL# print as nothing on a layout ending .html - a page is something you might show or publish, and a donor's home address is not what those seven words were written for. The one exception is a layout ending .rtf: that comes out as a document to print and hand to somebody, one item to a page, and there the donor markers are filled, because a donation form without its donor on it is not a form.

Last, #!HEADING#, with an exclamation mark after the hash, prints the word #HEADING# itself rather than the heading - of use only if you are explaining your own layout to somebody else, the way this page is explaining the program's.

Writing One Yourself

Start from a supplied layout rather than an empty file - Save As A New File on Sample of all fields or A Simple Web File, then Edit It, both on the EDIT OR CREATE A NEW TEMPLATE screen above. A supplied layout is read only, so there is no risk of changing the one the program came with by mistake.

A layout for one item must end .rtf, .html or .htm - whichever opens best in whatever you write it with. A layout for a whole category may end any of those three as well, or .docx: a Word book template, which is the one kind that does not build a page at all. Anything else dropped onto the templates window, or saved with another ending, is not offered in either list.

The Program Settings Screen

Everything the program lets you turn on and off is on one screen. Open Settings on the Reports and More menu and it comes up titled Program Settings, with a note across the top saying the options may be turned on and off without fear of changing the underlying data. That is the plain truth of this screen: the boxes decide what you are shown and which buttons you are offered, and not one of them alters an item, a file or a folder.

Nothing takes effect until you press Save Configuration, and then it takes effect at once - the program picks the changes up as the screen closes, so there is no restarting it to see them. Cancel, or closing the window with the X, leaves every box as it was, and puts the two pictures back as well if you changed one and then thought better of it.

The boxes are a list down the left side, and they are taken here in the order they sit in.

Show Item Detail on Description Page - adds, under the description of the item you are looking at, the lines that say where it came from and how it is filed: SOURCE, LOCATION, CATEGORIES, and then the item's ID and the type of file it is. A word you have searched for is marked in those lines as well as in the description, so when a search turns up an item because of its donor or its place you can see which field matched. Resting the pointer on one of them shows the whole of it, for a name too long to fit the line.

Allow Deletions - ticked, the Delete button is on the bottom row and works. Unticked, it is not there at all. This box is the only thing that takes the button away for good; the other reasons it goes quiet, such as nothing being selected or a slideshow running, grey it for the moment and give it back.

Show Camera GPS/Metadata on pictures that contain it - adds what the camera itself wrote into the picture: the model of camera, the date and time the picture was taken, and the latitude and longitude if the camera recorded them. It is only read from .JPG files, and a picture that carries none of it simply shows nothing. These lines go in underneath the detail lines above, so this box needs Show Item Detail on Description Page ticked as well - on its own it has nowhere to appear.

Slideshow Timer - puts a slider beside the Hide Tree button for how long each picture stays up before the next one. It reads Delay 5 seconds, and so on, as you move it, and at nought it reads Manual Mode and stays on the picture in front of you until you move on yourself. Without this box ticked there is no slider and a slideshow steps along by hand, which is what you want for showing one item across a room.

Album/Slideshow Order - makes the Album Order button appear when you are in Edit Mode on a category folder, which is where the order of an album is set. It is categories only: a Source folder, a Location folder and the RESULTS folder are not sequences and have no order screen. There is a section on albums above.

Create Book From Album - adds the Create Book button to the Album Order screen, which makes a document of the album in the order you have just set.

Show Expanded Trees - the three lists down the left open one level further when the program starts, so you see what is inside each heading rather than the headings by themselves. On a collection with a great many folders the shorter list is easier to get around, which is the reason this is a choice at all.

Show Logo on Description Page - puts your logo at the top of the description, above the item's title. It is the same logo the reports and the cards use, the one set by Change Report Logo on this same screen.

Add watermarks and rotation when adding an image file - when you attach a .JPG, .TIFF, .PNG or .BMP file, the watermark screen opens first. You can turn the picture upright there and write a line across it, and the copy that comes out is the one that gets filed. The file on your disk is left exactly as it was. If the item's title is still empty, what you typed for the watermark is used for it.

Delete Files as they are entered - removes the original file from wherever you picked it up, after the item has been made and the archive's own copy of it has been written. It is meant for working through a folder of things to be entered: what is left in the folder is what you have not done yet. It applies only to the file brought in for a new item, and only once that item's copy is safely in place.

The right hand side of the screen holds the two pictures the program uses, each with a preview above its button, and one button that leads to everything about the way the program looks.

Change Program Graphic - the picture shown whenever there is nothing else to show: before anything has been picked, and on an item that has no picture of its own, such as a sound file or a document. It must be a .JPG and it is scaled to the frame it goes in.

Adjust Screen Settings... - one screen for everything about how the program looks, with its own Done button at the bottom which saves and closes it.

  1. Colors - a row of looks to choose from, each one shown as a small sample. Click the one you want and the program restarts to come up in it.

The Buttons on the Main Screen

A button is enabled only when it can do something, so one that is greyed is telling you something. Either a thing is missing - Save stays grey until all five of the needed fields are filled in and something has actually changed - or the program is in the wrong mode for it.

Where a button has a key of its own, the key is named with it below. The keys work while you are looking at the collection, and only then: in Edit Mode, and while the cursor is in the search box, a letter is just a letter. Each one does nothing unless its own button is enabled, so the key is never able to do something the button could not.

Save and Delete have no key, by intention. They must be clicked with the mouse, deliberately, because neither should ever happen by a stray keystroke.

Add, or the A key - clears the form and goes into Edit Mode ready for something new. Nothing is written by pressing it.

Edit, or the E key - takes the item on screen into Edit Mode so its boxes can be changed. Once you are in, the same button reads Cancel, and pressing it comes back out with the item as it was.

Save - writes the item: the file is copied into the archive, the record is written beside it, and the folders it belongs in are linked up. If nothing is attached it asks first, and says why a file is wanted - the form as you have filled it in becomes the item's supporting document if you go ahead without one. A large file takes a moment and the cursor says so.

Cancel Changes - puts every box back to what the item said when you went in, and leaves Edit Mode. The screen comes back to its browsing shape, with the picture full size again.

Delete - removes the item on screen, and only that one. It asks first, and after that the item is out of the collection. To clear out a group of items, and to keep a way of changing your mind, use the backup route described under Deleting: One Item, or Several above.

Attach Picture Or Other File - picks the photograph, document, sound or video that the item is about. It is copied in and the file you chose is left where it was. If the item already has a file, you are asked whether the new one is to replace it or to serve as a display picture - a picture to look at for an item whose real file cannot be shown, such as a document.

Read Text From Image - reads the words out of the attached picture and puts them in the Description if that is empty, and in Provenance if it is not. It says READING... while it works, which on a big scan is a few seconds. The button is only there when there is text in the picture to read, and only on a computer that has the text reading support installed, so a copy of the program without it simply never offers it.

Open Item, or the V key, or the O key - opens the attached file in whatever this computer uses for that kind of file. If the picture has been turned, what opens is a turned copy; the archived file itself is never written to, because its bytes are the item's identity.

Browse, or the B key - opens the picture browser on the folder you are in: a screenful of tiles to walk the collection by eye and pick an item. It will not go outside the collection.

Hide Tree, or the plus key on the number pad - puts the picture up on the whole window with the lists out of the way, and steps through the items in the folder you are in. Adding, editing and deleting are switched off while it is up, because it is a screen for showing rather than working. The same button then reads Show Tree and brings everything back.

Album Order - opens the screen where the order of a category is set. It appears in Edit Mode on a category folder holding at least two items, and is not offered on a folder of more than two thousand - a screen of that many pictures cannot be built.

The two arrows, or the left and right arrow keys - the navigation bar above them says which of how many found items you are looking at, and the arrows step through them. They come round again at either end rather than stopping.

SOURCE, LOCATION and CATEGORIES - bring the matching list to the front, which is all they do if the item is filled in. Pressed in order while adding, they do something better: the third press on SOURCE fills in the last item's source, a fourth press adds its location, and a fifth all of its categories. Entering a box of similar things, that leaves only the title, the description and the file to do.

Add or Edit Source, Add or Edit Location, Add or Edit Categories - one button that follows whichever list is in front of you, and opens the screen for adding to that list or renaming part of it. It is there in Edit Mode only.

Search - searches the whole of every item's record for what is in the box beside it. Pressing Enter in the box does the same. What it finds is added to the RESULTS folder rather than replacing what is there, so several searches build one set. The tick box Search "Entered by" field narrows it to who entered the item instead.

Clear Result Folder - empties RESULTS, and says on its face how many files are in there waiting. It deletes nothing: what sits in that folder is the same single file each item already is, shown there as well.

View Result Folder - opens the picture browser on RESULTS, which is the quickest way to look over what a search gathered.

Where the Collection Lives

None of this needs to be known to use the program. It is here because somebody always asks, and because knowing it makes the one rule above make sense.

Each item has a folder of its own, named by the hash of its file: a forty character number worked out from the contents of that file and nothing else. Inside it are the file itself under the same name with its original extension, a DATA.txt holding the item's fields, and DISPLAY.JPG, a smaller picture the program draws on screen because a full size photograph is slow to put up again and again. DISPLAY.JPG is not precious - it makes itself again if it goes missing.

All of those item folders live in one place, Items, and that is the collection. The folders you browse - the sources, the locations, the categories, the albums - hold links to those same files rather than copies of them, which is why an item filed in five places takes the space of one. Rebuild Archive throws that browsable tree away and lays it down again from Items, which is why anything put into those folders by hand does not last and why nothing of value is lost when they are rebuilt.

An item whose file is not a picture - a video, a sound, a document - can be given a picture to show instead. Attach the second file and answer No when asked whether it is to replace the first: it becomes the display picture, and the item keeps the identity its real file gave it.

A backup is a single file ending .VAB. It is an ordinary zip file with a name of its own, holding everything needed to put the collection back: every item, every record, the thumbnails and the album order.

The Museum Version

With it unticked none of that is on the screen, and none of this section applies - which is why you are only shown it when the box is ticked.

What the box turns on belongs to the installation rather than to one collection, so the accession fields, the extra fields and the sign-in screen are available to every collection on the machine. Which of them you actually use is then a matter of the five boxes described just below.

The Five Boxes at the Top of Program Settings

Historical Society - Museum Version - with this ticked an item carries the date it was accessioned, its accession number, and a Donor Expectations box for whatever the donor asked of you: a condition on the gift, a wish about how it is shown, anything you will want to be able to read back years from now. Untick it and those three are hidden.

The date and the number appear on an item once it has actually been accessioned. Until then there is nothing to show and they stay out of the way, which is why a brand new item does not seem to have them.

It is worth settling this one before you enter anything. Nothing already entered comes to harm by ticking it later - the fields are simply empty on those items - but accession details are far easier to put in while the item is in front of you for the first time.

Accession Form Creation - puts a Create Accession Form tab on an item in Edit Mode, when that item is complete and has not been accessioned yet. That tab is where the deed of gift for the donor to sign is made, covering everything that donor has given you that is still waiting. The whole job, step by step, is the last part of this section.

Accession Number Overide - the program makes an accession number of its own out of the date and time, and this box lets you use your own instead. With it ticked, the accession number on the form can be typed into. Type it before you pick the items, because the number fills itself in the moment you choose the first one. Whatever is in that box is the number that gets used, with a dot and the count of items on the form after it. If you have no numbering of your own, leave this box alone: a number the program makes is built from the moment it was made, so no two forms are ever given the same one.

Show Metadata Box - adds a panel of thirteen more fields to an item in Edit Mode, for the things this program has no box of its own for. Twelve of them come named: Contributor(s), Material, Size, Date, Time Period, Copyright, Publisher, Creator, Place of Creation, Materials and Techniques, Condition and Appraised Value. The thirteenth has no name on it until one is given. None of them is required, and the panel says as much at the top of itself - fill in whichever apply to the item in front of you and leave the rest.

What you put in them is written into the spreadsheet of the whole collection as columns of its own, headed with the field names, so it can be read back and sorted outside the program.

The names are a plain list, one to a line, and a collection can have its own. Put a file called MetaFields.txt in the collection's own data folder - the one holding Items - and those names are what that collection's thirteen boxes are called; every other collection on the machine carries on with the ones the program came with. A rock collection can be asking for Species, Locality and Hardness while the museum collection beside it still asks for Contributor(s) and Appraised Value.

One thing to know before changing a list that is already in use: the values are stored by position, not by name. Rename the third field and whatever was typed into the third box is now labelled with the new name. On a collection with nothing in those boxes yet it costs nothing; on one that has been filled in, read down the list first.

Logging In

With Require Login ticked, the program opens on a sign-in screen showing the name of the collection being opened and its logo, a list of names, and a box for a password. There are three ways past it.

As yourself - pick your name and type your password. You can add, edit and delete items, and the menus are all there.

As ADMIN - pick ADMIN and type the administrator's password. Everything a user can do, and the list of users opens for editing underneath.

As a guest - leave the password box empty and press the button. A guest can look at everything, search, read descriptions and see pictures, but Add, Edit Mode and Delete are switched off and the menu bar is not shown. Closing the sign-in screen with the X, or pressing Escape, is the same as choosing guest.

The button always says what pressing it is about to do. It reads Login as GUEST while the password box is empty, changes to Log In as your name the moment a password that fits is typed, and says Password Not Accepted while a wrong one is in the box - so a mistyped password is visible before you commit to it, not afterwards when something will not work.

A wrong password is refused rather than quietly let in as a guest. The box is cleared so the next try starts clean, and you can type it again or empty the box and look around instead.

Require Login is a setting of the collection, so one collection on a machine can ask and another not.

There is no logging out. Nothing signs you off part way through, and nothing times out: when you have finished, close the program, and the next person to open it is asked who they are.

Adding and Removing Users

Choose ADMIN on the sign-in screen and type the administrator's password, and the user list opens below. One name to a line. To give somebody a password, type the name, an upright bar, and the password:

MONA|her password here


Press Save List and it tells you how many users were saved and how many of them have a password. A user with no password is listed, and can be given one later, but until then they can only get in as a guest.

Passwords are not kept as you typed them. They are scrambled on the way to the file in a way that cannot be turned back, which is why the list shows names only when you reopen it and never shows a password back to you. Typing a name on its own leaves that user's password exactly as it was; only a name with a bar and a new password changes one.

The administrator's password is fixed inside the program. It cannot be changed from the user list and it is not written in this help file, so no amount of editing the list can lock an administrator out of a collection.

The list of users belongs to the installation and not to one collection, so the same people are offered whichever collection is being opened.

Setting Up Who Logs In

From a copy that nobody has to sign into, the whole arrangement takes four steps.

  1. Open Settings on the Reports and More menu and tick Require Login. Save it.
  2. Close the program and start it again. The sign-in screen is there now.
  3. Choose ADMIN, type the administrator's password, and the user list opens underneath.
  4. Type each person on their own line as NAME|their password, and press Save List.

From then on each of them picks their own name and types their own password, and anyone else who sits down at the machine can look but not change anything. Their name is also written onto every item they enter, which is what the "Entered by" search looks at.

Two things worth deciding before you do it. Require Login belongs to the collection, so a reading-room collection can ask while the working one does not. And a person with no password is not locked out, they are a guest - which is a perfectly good answer for somebody who should see the collection and not touch it.

An Accession, from the Item to the Signature

This needs Accession Form Creation ticked in Program Settings.

The form is made from the item rather than from a separate screen, and it covers one donor at a time. Everything that donor has given you that has not been accessioned yet can go on the one form.

  1. Find any item from that donor and press Edit. The item must be complete and not already accessioned, and a Create Accession Form tab then appears beside the item's details.
  2. Open that tab. The donor's name and address are shown, from the donor's own record: first and last name, address, town, state, postcode, email and telephone. Fill in or correct what is missing - this is what prints at the head of the deed of gift.
  3. Underneath is everything of that donor's that is waiting to be accessioned. Pick the ones this form is for. Hold Control to pick several, or Shift to pick a run of them.
  4. The accession number fills itself in as soon as you choose something, and the number on the form is that number and then how many items are on it - MU20261021143000.6 for six of them. If Accession Number Overide is ticked you can type your own number instead, before choosing the items.
  5. The form builds itself on screen as you pick, with the logo, the donor's address, each item with its picture and description, the gift wording and the two signature lines. Read it there before you make it.
  6. Press Create Accession Sheet. The document is written into a folder called Virtual Archive Output in your home folder and opened for printing.

Every item on that form is given the accession number at the same moment, so they stop being offered on the next form and the number shows on each of them from then on. That is the whole of what accessioning changes: the item is not moved, not altered, and its ID is untouched - an accession number and an ID are two different things, and the item keeps both.

Print it, have the donor sign it, and keep the paper. The program made the document; it is not the record of the signature.

What the Words Mean

Seven words do most of the work in this program, and they are worth getting straight before anything else.

SOURCE - where or who the item came from. A donor, a purchase, a find.

LOCATION - where it physically is now. Storage Room 1/Shelf 4/Folder 5, Cemeteries/Hill Top, Streets/Maple St. A location can be as deep as you like; each part after a slash is a folder inside the one before it.

CATEGORY - what the item is, for finding it by subject: Vehicle, Photo, Children, Military/War/WWII, Minerals/Quartz. You make these up to suit the collection, and an item can carry up to sixteen of them. Past that the program says so and takes no more.

TITLE - a short description, which serves as the item's caption and as the name it is filed under in every folder it appears in. Two items may have the same title.

DESCRIPTION - the story: what the item is, what it is made of, how big it is, what condition it is in. There is no length limit worth worrying about.

PROVENANCE - the record of ownership and history, used as a guide to authenticity. Not required, and the part nobody can reconstruct later.

ITEM - one entry in the collection: a file, a record of the fields above, and a thumbnail, kept together.

Three more that describe the program rather than the item.

THE THREE LISTS - Source, Location and Categories, down the left of the screen. They are folders holding the items, and clicking through them is how you walk the collection.

THE ID - a short code on each item, worked out from the file attached to it. It is not a number handed out in turn. There is a section on it below, because two useful things follow from it.

RESULTS - the folder a search puts its findings in, and what the reports are built from.

Installing It, and Registering

The program runs on Windows, on a Mac and on Linux. It will work on a modest machine, and a bigger collection asks for more disk rather than more computer. A screen of 1920 by 1080 is a comfortable size to work at; on a 4K screen set the Screen choice in Adjust Screen Settings to 4K so the type and the lists come up at a sensible size.

Installing. Run the setup file and take the offered answers. It puts the program in place and leaves your collections alone - they are kept apart from the program, in your own user folder, which is what makes the next part safe.

Updating. Run a newer setup file over the top of the old one, the same way. The collections, the settings and the list of people are untouched, because none of them live in the program's own folder.

Registering. Until a copy is registered it works as a trial and stops at a hundred items. The code you were sent by email goes in from the Reports and More menu, at the item that reads Register Virtual Archive until a copy has been registered and Create New Collection afterwards. Paste the code in, and the program restarts to take it up.

If the code names a collection you already have, it opens that one and applies the registration to it rather than starting an empty collection beside it.

More Than One Collection

One copy of the program can hold several collections, each entirely separate: its own items, its own folders, its own title in the window. A historical society and a personal collection of minerals can sit side by side without ever mixing.

Which one you are in is shown in the title bar across the top, and the drop-down above the Source list is how you change it. Picking another collection loads it: the lists are read again and the screen clears, which on a large collection takes a moment and says so.

To make a new one, use the registration item on the Reports and More menu, described just above. Each collection comes from its own code.

To get rid of one, take its items out first - make a full backup of it, then use Delete Items Contained In A Backup File on that backup, which empties it while leaving you the backup to change your mind with. Then run Rebuild Archive. Finding nothing left, it asks whether the collection should go, and if you say yes it is taken off the list. The folder itself stays on disk untouched, so nothing is lost in the moment of saying yes.

Adding an Item, Start to Finish

Five things are needed before an item can be saved: a source, a location, at least one category, a title and a description. The Save button stays greyed out until all five are there, so a Save you cannot press means one of them is missing.

  1. Press Add. The screen clears and goes into Edit Mode, ready for something new.
  2. Press Attach Picture Or Other File and choose the photograph, document, sound or video. It is copied into the archive and the file you picked is left where it was. Attaching nothing is allowed, and the program then makes a file out of what you typed instead, but an item with a picture is worth far more to whoever opens it later.
  3. Press SOURCE and click, in the list on the left, who the item came from. If the name is not there, add it on the Add Source tab at the bottom left. If nobody knows, DONOR UNKNOWN is a real answer and the item still saves.
  4. Press LOCATION and click where the item physically is. NOT PLACED counts here in the same way.
  5. Press CATEGORIES and click one, or several. Clicking a category you have already chosen removes it again.
  6. Type the title in the box at the top. It is the name the item is filed under in every folder it appears in, so write it the way you would want to find it.
  7. Fill in the description: what the item is, with any distinguishing details, materials, dimensions and condition. Provenance, underneath, is for previous owners, dates and history. It is not required, and it is the part nobody can reconstruct later.
  8. Press Save.

Nothing at all is written until Save is pressed, and Cancel Changes leaves the item exactly as it was.

Entering a run of similar items is quicker than this list makes it look. The SOURCE button pressed three times fills in the last item's source, a fourth press adds the location, and a fifth the categories, so the second item of a box usually needs only a title, a description and the file.

Why an Item Has an ID, and the One Rule

Every item carries an ID, shown on the item screen as something like A1B-2C3. It is not a number handed out in order. It is worked out from the file itself, from the picture or document attached to the item, so the file and the ID are one fact written two ways. Two things follow, and both turn up in ordinary use.

The same file cannot be added twice. Attach a file that is already in the collection and the program says so and stops, because that file is what tells one item from another. It offers the two honest ways out: attach it to this item as a display picture, or change the file itself - a single different pixel is enough - so that it genuinely is a different file. This is deliberate. Two items that are the same file are not two items.

One copy of your file is filed in several places at once. An item filed under a source, a location and three categories shows up in five folders, and it is the same single file each time rather than five copies of it. A collection does not swell because its items are well filed.

And the rule that protects both: do your renaming, moving and deleting inside the program, not in Explorer or Finder. A file altered out there no longer matches its ID, and the program can no longer tell that the item is itself - which is how the same thing can end up in the collection twice. The folders you browse are also built fresh each time Rebuild Archive runs, so anything put into them by hand is gone at the next rebuild. The items are what those folders are built from, and they are the thing to look after.

Changing an Item That Is Already In

Find the item first. Click through the Source, Location or Categories lists to the folder it is in, and if the folder holds several items the navigation bar and the two arrows step through them. A search is the other way in, and what it finds lands in the RESULTS folder.

With the item on screen press Edit. Every box can be changed. Source and Location are picked the same way as when the item was entered. Categories toggle: click one to add it, click it again to take it off. The file itself is changed with Attach Picture Or Other File, and because the file is what gives the item its ID, replacing it gives the item a new one - which is the one case where that happens.

Nothing is written until Save, and Cancel Changes puts every box back to what it was.

Moving Something to Another Place

A location is a path, and the slashes in it are real containers inside one another. CORNER CABINET\BOX 1 means box 1, which is in the corner cabinet; CORNER CABINET\BOX 1\TRAY 2 is a tray inside that box. The lists down the left draw it as folders inside folders because that is what it is.

So when the box itself is moved - out of the corner cabinet and onto shelf 7, say - what you want is for every item in it, and everything nested inside it, to come along. That is one job in this program, not one job per item.

Moving One Item

Press Edit, press LOCATION, and click the new place in the list. If the place does not exist yet, add it with Add or Edit Location first. Press Save. That item is now filed there and nothing else has changed.

Moving a Whole Box, with Everything In It

This is the one for a real move: the box has gone somewhere else, and its contents went with it.

  1. Press Browse and walk to the box: open (LOCATION), then CORNER CABINET, then BOX 1. You are now standing in the folder that is going to move.
  2. Press Move Directory at the bottom. A screen opens titled Move This Folder - choose destination.
  3. Click where it is going - BOX COLLECTION - and press Move Here. The box keeps its own name and becomes part of what you clicked, so CORNER CABINET\BOX 1 becomes BOX COLLECTION\BOX 1, the same as dragging one folder onto another.
  4. You are told how many items are about to be moved and asked to say yes. Read the number: it should be the number of things in that box. Then it works through them, counting as it goes, and says MOVE COMPLETE with the old and new addresses.

Typing a destination instead. The same screen has a box to type in, and what you type is the whole new address rather than a parent to sit under: type BOX COLLECTION\BOX 1 and that is exactly where it lands. Typing is also the way to move something into a place that does not exist yet - STORAGE ROOM 2\SHELF 4 is made on the way - and (TOP LEVEL) at the head of the list means no parent at all, a place of its own.

What actually happens. Every item whose location starts with the old path has that part of it rewritten, so the box, the trays inside it and every item in any of them all travel together and keep their arrangement. The folders you browse are relinked to match, and folders left empty by the move are cleared away.

The items themselves are not touched. The files stay exactly where they are in the archive, the IDs do not change, and nothing is copied - only the address written on each record, and the folders built from it.

There is no undo button for this. There is no need for one either: moving it back is the same job in the other direction, and the program tells you the count before it starts, which is the moment to notice if you are standing in the wrong folder.

The Other Way In

From an item rather than from the browser: press Edit on any item in that box and press Add or Edit Location. The box's own address is already filled in beside Rename From - it is the address the item you are on carries, which is why you open this from an item in the box you mean to move. Type the new address beside Rename To and press Rename / Move Location. It is the same move, with the same confirmation and the same count - it simply starts from an item you have in front of you instead of from the folder.

This is also how a place gets a better name. The old address and the new one are both just text; renaming BOX 1 to MAPS AND PLANS and moving BOX 1 under BOX COLLECTION are the same operation, which is why one button does both.

Categories Move the Same Way

Everything above works on a category as well. Browse into the category and press Move Directory, or use Add or Edit Categories and its rename button. A category that has a display sheet keeps it, and sub-categories travel with their parent exactly as trays travel with their box.

Sources are different: an item's source is where it came from, which does not change because the thing was put somewhere else. There is no move for a source folder, and there should not be.

Deleting: One Item, or Several

Delete removes the item you are looking at, entirely, and one is all it removes. It asks first, and once you have said yes that item is out of the collection: out of every folder it was filed in, out of the lists, out of the reports. There is no undo. Treat it as gone, because it is.

It is not the preferred way to delete. It is there for the single obvious mistake - the duplicate, the picture of the inside of a lens cap - where there is nothing to think about. For anything else, use the way described below, which asks you to make a backup file first and so hands you the means of changing your mind.

Deleting Several, and Keeping a Way Back

Clearing out a group of items is done through Backing Up and Restoring, on the Reports and More menu, in two steps: make a backup of the items that are going, then delete them using that backup file.

  1. Search for what is to go, so that those items are the ones in the (RESULTS) folder. Run several searches if it takes several - results add up rather than replacing each other - and look through RESULTS until it holds exactly what you mean to remove.
  2. Open Backing Up and Restoring, choose Backup (Export) Result Folder and press Accept. You are asked where to put the file; it is given a name ending .VAB, and it holds those items whole.
  3. In the same screen, choose Delete Items Contained In A Backup File, press Accept, and pick the file you have just made. Exactly the items in that file are removed from the collection, and nothing else is touched.
  4. Run Rebuild Archive afterwards so the folders you browse match what is left.

The same file brings them back. Deleting with it does not consume it or change it - it is a file of its own, outside the collection - so changing your mind needs nothing clever: open Backing Up and Restoring again, choose Restore (Import) Backup File, and pick that same file. It is the ordinary restore, doing the ordinary thing, and the items return with their sources, locations, categories, titles, descriptions and pictures exactly as they were.

That is the whole reason this is the preferred way round. The file you had to make in order to delete is the same file that undoes it, so the undo exists before the deletion does. Nothing has to be remembered, and nothing has to be dug out of anywhere.

So the order of work is: gather, back up, delete. Keep that .VAB somewhere sensible for as long as there is any chance of wanting those items again - a year, say, or for ever if the disk can spare it. It is the only way back, and it costs nothing to keep.

This is also how part of a collection is handed to somebody else, or split into a collection of its own: the same backup file that lets you undo the deletion is the file they restore at their end. There is a section on backing up below that goes through all of it.

Importing a Whole Folder

A folder of scans or photographs can come in all at once instead of one item at a time. It is on the Reports and More menu as Import a Folder..., and the screen says what it is about to do before it does it.

  1. Tick what to bring in: Pictures, Music, Video, Documents, or Everything in the folder, whatever it is. If what you want is not one of those, type the file types in the box instead, like tif, cr2, wav.
  2. Press Choose Folder... and pick the folder. Everything in it, and in every folder inside it, is considered.
  3. Fill in the Source and Location that will go on the whole batch, and press OK.

"Everything in the folder, whatever it is" brings in literally everything under the folder you choose, without asking file by file - which is the point of it, and exactly why it is worth a moment's thought before pointing it at a folder you have not looked through yourself. An old folder can hold more than you remember: thumbnails and cache files a camera or a phone left behind, a stray download, half a dozen near-duplicates of the same shot. None of that is sorted out on the way in - it all becomes items - and taking it back out afterwards means finding and deleting each one by hand rather than one folder you could have left out to begin with. Know roughly what is in a folder before choosing Everything on it; where you do not, tick just the kinds you actually want and the rest is left alone.

Both of those boxes can be left empty, and what happens then is useful rather than a fallback. An empty Source files the batch under the date and time the import was run, which is how you find that one batch again afterwards. An empty Location groups the items by what they are - PICTURES, MUSIC, VIDEO or FILES - with one exception: an .MP3 that carries its own artist and album tag is filed by them instead, as MUSIC\ARTIST\ALBUM, stopping at the album so that every song on it still shares one folder to browse rather than each sitting alone in one of its own. A track number in the tag goes onto the front of the title, not into the location.

Each file becomes an item, and it is the item's category - not its location - that keeps the folder structure you already had: filed under IMPORT, by the same file-type grouping as above, and then by the one folder immediately holding the file, rather than the whole chain of folders above it. The filename becomes the title, and a song uses the title in its own tag if it has one. Whatever a file knows about itself is kept: the camera and the date from a photograph, the artist and album from a song, the author and title from a document.

Nothing in the folder you point at is moved, renamed or altered - the files stay exactly where they are and the collection gets its own copy. A file that is already in the collection is recognised and skipped, so running the same import twice does not bring anything in twice.

What the import cannot do is write your descriptions. The items arrive with a title, a source, a location and their categories, and the description box is empty and waiting. That is the work; the import is only the carrying.

What Rebuild Archive Does, and When to Run It

Rebuild Archive is on the Reports and More menu. It throws away the folders you browse - the source folders, the location folders, the categories, the albums - and builds every one of them again from your items.

That sounds alarming and is not, because those folders were never where anything was kept. They are a way of looking at the items, built out of what each item's record says, and they can be made again at any time. Your items are not rebuilt. They are what the rebuild is built from.

Run it when the folders and the items have got out of step:

  • after restoring a backup - though the program runs it for you then;
  • when a folder looks wrong, or empty, or an item is not where it should be;
  • after anything has been moved about underneath the program.

It shows a bar and a percentage while it works, and a collection of several thousand items takes minutes rather than seconds. Closing the window stops it: it tells you how many items it managed and asks you to run it again to finish, and because it starts over from the items each time, stopping costs nothing but the time already spent.

Backing Up, and Putting a Collection on Another Computer

Backing Up and Restoring on the Reports and More menu does both jobs, and the screen is in three parts: make a backup, delete items using a backup, and restore from a backup.

To make one, choose Full Backup and press Accept. You are asked where to put it, and the box opens in your home folder rather than in the collection, because the one place a backup must never go is inside the thing it is backing up. Put it on another drive - the drives you can reach are listed down the side of that box. The file is given a name ending in .VAB and it holds the whole collection: every item, every record, the thumbnails, the categories, the album order and the accession records.

It is written under a temporary name and only given its real one once it is finished and has been checked. A backup that was interrupted is therefore never left sitting there under the name of a good one, which is the worst way for a backup to fail.

To send somebody part of a collection rather than all of it, search for what they should have so that it lands in the RESULTS folder, then choose Backup (Export) Result Folder. That makes a .VAB of only those items.

To put a collection on another computer:

  1. Install the program there and open it.
  2. Make the collection: Create New Collection on the Reports and More menu, and give it a name. On a copy that has not been registered yet, that same menu item reads Register Virtual Archive and asks for the code you were sent instead.
  3. With that collection open, go to Backing Up and Restoring, choose Restore (Import) Backup File, press Accept, and pick the .VAB file.
  4. Let it finish. It says REBUILD ARCHIVE next and then does it for you.

Restoring adds what is in the backup to the collection that is open. It does not replace it and it does not empty it first, which is what makes it useful for joining two bodies of material as well as for moving one. The same choice can change what the items say as they come in: fill in Change Source, Change Location or Add Category before pressing Accept, and every item in the backup arrives with that instead. Leave those boxes empty and the items come in exactly as they were.

A Routine Worth Keeping

Knowing how to make a backup is not the same as having one. What works, from societies that have been doing this for years: a full backup onto two drives once a year, one kept where the collection is and one kept somewhere else entirely - a board member's house, another building - so that one fire or one theft cannot take both. Make another whenever you have just done a season's worth of entering, while it is fresh enough to be worth protecting.

Write the date on the drive, keep the last one rather than writing over it, and eject the drive before pulling it out - on Windows through the arrow at the bottom right of the screen, on a Mac by dragging it to the wastebasket, on Linux with the eject symbol beside its name. The file is large and the last of it may still be being written when the copying looks finished.

And test one. Restoring a backup into a spare collection, once, tells you the drive is readable and the file is whole - which is a thing worth knowing before the day you need it.

Delete Items Contained In A Backup File is the other direction: it removes from this collection exactly the items that are in the backup file you choose. This is the preferred way to delete anything more than a single obvious mistake, because the file itself is untouched - restoring that same file afterwards puts every one of those items back.

Searching: What Is Looked At, and How

Type into the search box on the Search tab and press Search, or just press Enter. Capital letters make no difference.

What is searched is the whole of an item's record, not only its description: the title, the description, the provenance, the source, the location, every category, the dates, the file type, and anything a photograph or a song brought in with it. That is why an item can come back for a reason that is not visible in its description, and why the match is marked in SOURCE, LOCATION and CATEGORIES as well as in the words.

What you type is looked for as one piece of text. There is no wildcard, and there is no way to ask for two words in different places: BRAGG FARM finds records where that runs together as written, not records that happen to hold both words apart. Shorter is therefore usually better - BRAGG finds everything BRAGG FARM would have, and more.

Searching for a single full stop . returns every item in the collection. Every record stores the file's extension with its dot, so a full stop is in all of them.

The tick box Search "Entered by" field changes what is looked at rather than adding to it: with it ticked, the search looks only at who entered the item, which is how you find a volunteer's work for the afternoon. Untick it to go back to searching everything.

A search of two letters or fewer finds items but marks nothing, which stops a short word painting the whole screen yellow.

A search of a large collection is not instant - several thousand items take a little while, and the bar across the top is there to say that something is happening rather than nothing. When more than one item is found, the navigation bar shows which of how many you are looking at, and the arrows move through them.

The RESULTS Folder, and Sharing Part of a Collection

Everything a search finds is put into a folder called (RESULTS), and that folder is what the rest of the program works from when it is asked to produce something.

A search adds to it and never empties it. Search for one family, then another place, then a year, and all three sets are gathered together - and an item already there is not put in twice. The only thing that empties it is the Clear Results Folder button.

Clearing it deletes nothing. What sits in that folder is the same single file the item already is, shown there as well; removing it removes the showing, not the item. The same is true of the folders you browse.

Two more buttons sit beside it. Add Selected Directory to Results puts everything in the folder you are looking at into RESULTS, which is how to gather a whole category without searching for it. View Result Folder shows you what you have collected so far.

Once it holds what it should, there are three things to do with it:

  • Spreadsheet of (RESULTS) directory on the Reports and More menu writes a spreadsheet of them;
  • Backup (Export) Result Folder on the Backing Up and Restoring screen makes a .VAB of just those items, which is how you send somebody part of a collection;
  • and anything you then do to the items themselves is ordinary work - RESULTS is a way of holding a set, not a copy of it.

A Spreadsheet of the Whole Collection

The 'Spreadsheet of (RESULTS) directory' option builds its report from whatever is in the RESULTS folder, so to get a report covering everything, first put everything into RESULTS: search for a single full stop . and every item in the collection is returned.

This is complete, not an approximation. The search reads the whole of an item's record, not just its description, and every record stores the file's extension with its dot - .JPG, .MP3 - so a full stop is always present, whatever the item is called and whatever was typed about it.

The FILE column, the fifth one, is a link rather than just a name: click it in the spreadsheet and the item's own file opens, so a line you are reading about can be looked at without coming back to the program. The LOCAL FILE LOCATION column near the end links the same way to where the item is filed under its source.

The spreadsheet is written as Full_Report.xlsx in the collection's data folder, and opens in whatever application handles spreadsheets on this computer. If nothing does, the file is still created and a window opens showing you where it is. Close the report before creating a new one - the file is overwritten in place, and a spreadsheet program holding the old copy open will go on showing the old figures.

Albums, the Order They Are In, and a Book

An album is a category like any other. Put the items into it the way you file anything else, and what makes it an album is that you can decide the order they are in instead of leaving them in the order they were entered.

Open the category, press Edit, and the Album Order button appears. It opens a screen of small pictures, numbered in their current order.

  1. Click the picture you want to move. It turns green.
  2. Click the picture you want it to sit at. The first one moves there and everything else shuffles along.
  3. Click a green picture again to change your mind instead of moving it.
  4. Press Save Changes when the order is right, or Quit Without Saving to leave it as it was.

Slides Across sets how many pictures are shown on a row, which is for your eyes while you work and has nothing to do with the order itself.

The order is kept with the category and is what you see from then on, in the folder and in a slideshow.

A slideshow. The Hide Tree button puts the picture up on the whole window with the lists out of the way, and steps through the items in the folder you are in. How long each one stays up is the slider beside it, and at nought it simply stays on the picture you are looking at, which is the way to show one item across a room. The slider is only there when Slideshow Timer is ticked in Program Settings. Press the same button, now reading Show Tree, to come back.

A book. With Create Book From Album ticked in Program Settings, the Album Order screen also offers Create Book. It makes a document of the album in the order you have just set: each picture at the size and position the card format gives it, with the title, the description and the provenance under it. It is written into a folder called Virtual Archive Output in your home folder, with the date and time in its name so a new one never writes over the last, and it opens in whatever handles documents on this computer.

The Create Screen: a Display Sheet for an Item or a Category

Highlight the item, or the category in the CATEGORIES list, then open the Reports and More menu and choose Create Display Sheet. The screen that opens has its controls at the top and the page itself underneath them: everything you change is redrawn there as you change it, so nothing has to be guessed at or produced to be looked at.

What Would You Like to Create?

Two choices at the top, and they decide which set of controls is on screen.

This Item is chosen when the screen opens. It makes a card for the one item you had highlighted.

This Category makes a page of a whole category: a heading, your own words, and every item in it. It is greyed out, with no category selected beside it, if you did not come in from a category - the reason is put next to the control rather than left for you to work out.

For One Item

Pick Template - the list of card layouts. Left on its first entry, the card is the program's own. Choose one of yours and it asks Build the page with this layout? with Run and Cancel, so a layout picked by accident costs nothing. The list then returns to its first entry, which is deliberate: it means choosing the same layout again still does something.

For a Category

Heading - the title that goes across the top of the page.

View In Browser - builds the page and opens it. The preview on screen shows the first twelve items, which is enough to see what the page will look like; the page it makes holds up to four hundred.

Layouts of Your Own

EDIT OR CREATE A NEW TEMPLATE, on either list, opens a screen of the layouts you have and the ones the program came with. Edit It opens one of yours to change, in whatever handles that kind of file. Save As A New File takes a copy of any of them - which is the only thing to do with a supplied one, since those are read only and stay that way. Delete throws one of yours away. Cancel closes it.

When you have finished, close the screen with the X. The heading and the words are saved on the way out as well as when a page is built, so a page written and not yet viewed is not lost.

What a Layout Can Ask For

Open Sample of all fields, the layout the program comes with, in a text editor, and short words in capitals between hash signs stand out everywhere: #HEADING#, #TITLE#, and so on. Each one is a marker. Wherever it sits in your file, the finished page has something real put there instead - the category's own heading, one item's own title - and everything else, every tag, every colour, every word you typed yourself, is left exactly as you wrote it.

Some markers are filled once, from the category itself, however many times they appear on the page:

#HEADING# - the title typed into the Heading box.

#CATEGORYTEXT# - the paragraph typed into the Words box.

#CATEGORY# - the category's own name, exactly as it is filed.

#ORGANIZATION# - your collection's name.

#COUNT# - how many items are on the page.

#ACCESSIONNUM# - a fresh accession number for the batch, worked out new each time, the same kind a single card gets.

#LOGO# - your report logo, already a complete picture rather than a filename. Put the marker itself where the picture should sit; there is nothing to put it inside.

The rest are filled once for every item, and only work between a pair of #EACH# and #END# markers. Put those two around whatever should repeat - one cell of a table, say - and the program copies that piece once for every item in the category, filling it fresh each time:

#TITLE# - the item's name.

#THUMB# - the item's own picture, already complete; #FILENAME# is the same marker, under the name a card layout knows it by.

#DESCRIPTION#, #PROVENANCE# and #METADATA# - the item's own description, provenance and metadata.

#ID# and #SOURCE# - the item's short identifier, and who it came from.

#NUMBER# - which one this is on the page: 1, 2, 3 and on.

#NEWROW# - put at the very front of the repeated piece, it becomes a new table row every three items, and nothing at all on the first.

A category page is not the donor's own business card, so #DONOR#, #ADDRESS#, #CITY#, #STATE#, #ZIP#, #PHONE# and #EMAIL# print as nothing on a layout ending .html - a page is something you might show or publish, and a donor's home address is not what those seven words were written for. The one exception is a layout ending .rtf: that comes out as a document to print and hand to somebody, one item to a page, and there the donor markers are filled, because a donation form without its donor on it is not a form.

Last, #!HEADING#, with an exclamation mark after the hash, prints the word #HEADING# itself rather than the heading - of use only if you are explaining your own layout to somebody else, the way this page is explaining the program's.

Writing One Yourself

Start from a supplied layout rather than an empty file - Save As A New File on Sample of all fields or A Simple Web File, then Edit It, both on the EDIT OR CREATE A NEW TEMPLATE screen above. A supplied layout is read only, so there is no risk of changing the one the program came with by mistake.

A layout for one item must end .rtf, .html or .htm - whichever opens best in whatever you write it with. A layout for a whole category may end any of those three as well, or .docx: a Word book template, which is the one kind that does not build a page at all. Anything else dropped onto the templates window, or saved with another ending, is not offered in either list.

A marker must be typed exactly as shown, in capitals, with a hash sign on each side - #title# is not a marker and prints as those seven characters. The Program Settings Screen

Everything the program lets you turn on and off is on one screen. Open Settings on the Reports and More menu and it comes up titled Program Settings, with a note across the top saying the options may be turned on and off without fear of changing the underlying data. That is the plain truth of this screen: the boxes decide what you are shown and which buttons you are offered, and not one of them alters an item, a file or a folder.

Nothing takes effect until you press Save Configuration, and then it takes effect at once - the program picks the changes up as the screen closes, so there is no restarting it to see them. Cancel, or closing the window with the X, leaves every box as it was, and puts the two pictures back as well if you changed one and then thought better of it.

The boxes are a list down the left side, and they are taken here in the order they sit in.

Show Item Detail on Description Page - adds, under the description of the item you are looking at, the lines that say where it came from and how it is filed: SOURCE, LOCATION, CATEGORIES, and then the item's ID and the type of file it is. A word you have searched for is marked in those lines as well as in the description, so when a search turns up an item because of its donor or its place you can see which field matched. Resting the pointer on one of them shows the whole of it, for a name too long to fit the line.

Allow Deletions - ticked, the Delete button is on the bottom row and works. Unticked, it is not there at all. This box is the only thing that takes the button away for good; the other reasons it goes quiet, such as nothing being selected or a slideshow running, grey it for the moment and give it back.

Show Camera GPS/Metadata on pictures that contain it - adds what the camera itself wrote into the picture: the model of camera, the date and time the picture was taken, and the latitude and longitude if the camera recorded them. It is only read from .JPG files, and a picture that carries none of it simply shows nothing. These lines go in underneath the detail lines above, so this box needs Show Item Detail on Description Page ticked as well - on its own it has nowhere to appear.

Slideshow Timer - puts a slider beside the Hide Tree button for how long each picture stays up before the next one. It reads Delay 5 seconds, and so on, as you move it, and at nought it reads Manual Mode and stays on the picture in front of you until you move on yourself. Without this box ticked there is no slider and a slideshow steps along by hand, which is what you want for showing one item across a room.

Album/Slideshow Order - makes the Album Order button appear when you are in Edit Mode on a category folder, which is where the order of an album is set. It is categories only: a Source folder, a Location folder and the RESULTS folder are not sequences and have no order screen. There is a section on albums above.

Create Book From Album - adds the Create Book button to the Album Order screen, which makes a document of the album in the order you have just set.

Show Expanded Trees - the three lists down the left open one level further when the program starts, so you see what is inside each heading rather than the headings by themselves. On a collection with a great many folders the shorter list is easier to get around, which is the reason this is a choice at all.

Show Logo on Description Page - puts your logo at the top of the description, above the item's title. It is the same logo the reports and the cards use, the one set by Change Report Logo on this same screen.

Add watermarks and rotation when adding an image file - when you attach a .JPG, .TIFF, .PNG or .BMP file, the watermark screen opens first. You can turn the picture upright there and write a line across it, and the copy that comes out is the one that gets filed. The file on your disk is left exactly as it was. If the item's title is still empty, what you typed for the watermark is used for it.

Delete Files as they are entered - removes the original file from wherever you picked it up, after the item has been made and the archive's own copy of it has been written. It is meant for working through a folder of things to be entered: what is left in the folder is what you have not done yet. It applies only to the file brought in for a new item, and only once that item's copy is safely in place.

The Pictures, and How the Program Looks

The right hand side of the screen holds the two pictures the program uses, each with a preview above its button, and one button that leads to everything about the way the program looks.

Change Program Graphic - the picture shown whenever there is nothing else to show: before anything has been picked, and on an item that has no picture of its own, such as a sound file or a document. It must be a .JPG and it is scaled to the frame it goes in.

Change Report Logo - your own logo, used at the head of the reports and the forms, on the cards, and on the description page when Show Logo on Description Page is ticked. A .JPG again. It is used at 300 pixels wide by 136 high, and one of another size is scaled to fit, which can cost it some sharpness - so it is worth giving it one already about that shape.

Either picture takes effect the moment you choose it and the preview above the button changes to show it. Leave by Cancel rather than Save Configuration and the one you had before comes back.

Adjust Screen Settings... - one screen for everything about how the program looks, with its own Done button at the bottom which saves and closes it.

  1. Colors - a row of looks to choose from, each one shown as a small sample. Click the one you want and the program restarts to come up in it.
  2. Screen - Regular screen or 4K screen, which says which of the two sets of sizes below is the one in use. The Reset beside each puts that whole set back to the sizes the program came with.
  3. Directory Text - the size of the type in the Source, Location and Categories lists, whether it is bold, and how wide the panel holding them is. Both sets of numbers are shown side by side so you can set one up without losing sight of the other. A name too long for the panel is cut off, so the type size and the panel width between them decide how much of a folder's name you can read.
  4. Description Text - the same three things for the description beside the picture. Whatever width you do not give the description is what the picture gets, so these are really one adjustment: wider text reads more like a page, narrower leaves a bigger picture.

Done saves that screen by itself. There is nothing further to press on the settings screen behind it for the sizes and the colours to stick.

The Buttons on the Main Screen

A button is enabled only when it can do something, so one that is greyed is telling you something. Either a thing is missing - Save stays grey until all five of the needed fields are filled in and something has actually changed - or the program is in the wrong mode for it.

Where a button has a key of its own, the key is named with it below. The keys work while you are looking at the collection, and only then: in Edit Mode, and while the cursor is in the search box, a letter is just a letter. Each one does nothing unless its own button is enabled, so the key is never able to do something the button could not.

Save and Delete have no key, by intention. They must be clicked with the mouse, deliberately, because neither should ever happen by a stray keystroke.

Add, or the A key - clears the form and goes into Edit Mode ready for something new. Nothing is written by pressing it.

Edit, or the E key - takes the item on screen into Edit Mode so its boxes can be changed. Once you are in, the same button reads Cancel, and pressing it comes back out with the item as it was.

Save - writes the item: the file is copied into the archive, the record is written beside it, and the folders it belongs in are linked up. If nothing is attached it asks first, and says why a file is wanted - the form as you have filled it in becomes the item's supporting document if you go ahead without one. A large file takes a moment and the cursor says so.

Cancel Changes - puts every box back to what the item said when you went in, and leaves Edit Mode. The screen comes back to its browsing shape, with the picture full size again.

Delete - removes the item on screen, and only that one. It asks first, and after that the item is out of the collection. To clear out a group of items, and to keep a way of changing your mind, use the backup route described under Deleting: One Item, or Several above.

Attach Picture Or Other File - picks the photograph, document, sound or video that the item is about. It is copied in and the file you chose is left where it was. If the item already has a file, you are asked whether the new one is to replace it or to serve as a display picture - a picture to look at for an item whose real file cannot be shown, such as a document.

Read Text From Image - reads the words out of the attached picture and puts them in the Description if that is empty, and in Provenance if it is not. It says READING... while it works, which on a big scan is a few seconds. The button is only there when there is text in the picture to read, and only on a computer that has the text reading support installed, so a copy of the program without it simply never offers it.

Open Item, or the V key, or the O key - opens the attached file in whatever this computer uses for that kind of file. If the picture has been turned, what opens is a turned copy; the archived file itself is never written to, because its bytes are the item's identity.

Browse, or the B key - opens the picture browser on the folder you are in: a screenful of tiles to walk the collection by eye and pick an item. It will not go outside the collection.

Hide Tree, or the plus key on the number pad - puts the picture up on the whole window with the lists out of the way, and steps through the items in the folder you are in. Adding, editing and deleting are switched off while it is up, because it is a screen for showing rather than working. The same button then reads Show Tree and brings everything back.

Album Order - opens the screen where the order of a category is set. It appears in Edit Mode on a category folder holding at least two items, and is not offered on a folder of more than two thousand - a screen of that many pictures cannot be built.

The two arrows, or the left and right arrow keys - the navigation bar above them says which of how many found items you are looking at, and the arrows step through them. They come round again at either end rather than stopping.

SOURCE, LOCATION and CATEGORIES - bring the matching list to the front, which is all they do if the item is filled in. Pressed in order while adding, they do something better: the third press on SOURCE fills in the last item's source, a fourth press adds its location, and a fifth all of its categories. Entering a box of similar things, that leaves only the title, the description and the file to do.

Add or Edit Source, Add or Edit Location, Add or Edit Categories - one button that follows whichever list is in front of you, and opens the screen for adding to that list or renaming part of it. It is there in Edit Mode only.

Search - searches the whole of every item's record for what is in the box beside it. Pressing Enter in the box does the same. What it finds is added to the RESULTS folder rather than replacing what is there, so several searches build one set. The tick box Search "Entered by" field narrows it to who entered the item instead.

Clear Result Folder - empties RESULTS, and says on its face how many files are in there waiting. It deletes nothing: what sits in that folder is the same single file each item already is, shown there as well.

View Result Folder - opens the picture browser on RESULTS, which is the quickest way to look over what a search gathered.

Where the Collection Lives

None of this needs to be known to use the program. It is here because somebody always asks, and because knowing it makes the one rule above make sense.

Each item has a folder of its own, named by the hash of its file: a forty character number worked out from the contents of that file and nothing else. Inside it are the file itself under the same name with its original extension, a DATA.txt holding the item's fields, and DISPLAY.JPG, a smaller picture the program draws on screen because a full size photograph is slow to put up again and again. DISPLAY.JPG is not precious - it makes itself again if it goes missing.

All of those item folders live in one place, Items, and that is the collection. The folders you browse - the sources, the locations, the categories, the albums - hold links to those same files rather than copies of them, which is why an item filed in five places takes the space of one. Rebuild Archive throws that browsable tree away and lays it down again from Items, which is why anything put into those folders by hand does not last and why nothing of value is lost when they are rebuilt.

An item whose file is not a picture - a video, a sound, a document - can be given a picture to show instead. Attach the second file and answer No when asked whether it is to replace the first: it becomes the display picture, and the item keeps the identity its real file gave it.

A backup is a single file ending .VAB. It is an ordinary zip file with a name of its own, holding everything needed to put the collection back: every item, every record, the thumbnails and the album order.
